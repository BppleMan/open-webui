# Connection protocols (R53 / P38)

Templates initialize the service address, authentication and compatibility profile. They do not restrict the wire protocol. Every connection offers Chat Completions, Responses, Anthropic Messages and Gemini GenerateContent; Ollama and Gemini Interactions remain extensions. A model inherits its connection unless `protocol_override` is set. Identity is independent of protocol, and discovery reuses all existing connection/upstream model records without merging historical variants.

`GET /api/v1/protocols` exposes the registry. `POST /api/v1/connections/resolve` previews routing without making a provider request or saving credentials. The same resolver handles discovery, server requests and owner-only browser configuration. Enter a service root (including any proxy mount), not a version prefix. Legacy versioned addresses are accepted. Persisted compatibility profiles handle OpenRouter `/api`, Gemini's OpenAI compatibility path, Azure deployments, and CPA RP identity. Authentication remains independent when changing protocol.

Migration OI7 adds nullable model overrides and replaces protocol-scoped uniqueness with a nonunique provider identity index. Existing matching modes become inherited; different modes remain overrides. Existing effective URLs are preserved, including unusual mounts marked for review. Changing settings does not mutate a detached in-flight call configuration. Existing ledger and native history are never rewritten. Signed history from an incompatible protocol is rejected rather than silently stripped.

Browser RPC explicitly carries protocol, full resolved URL and streaming mode. The browser validates these against owner-only, no-store configuration and obtains encrypted credentials through that endpoint. Native discovery pages are collected before application. No network/CORS error falls back to server execution or another protocol. Non-chat adapters keep their capability paths; they do not call the chat endpoint.

Connection models sort enabled-first when loaded, searched or reopened; saves from toggles preserve current ordering. Rows are 2rem on desktop and 2.5rem on mobile, with a five-row scroll region. The action row stays outside the scroller. Connection separators and duplicate vertical spacing are removed. Editor switches align to the trailing control column.

Validation includes populated SQLite/PostgreSQL migration fixtures, inherited/overridden identities, address resolution, two transports across the four protocols, signed tool round-trips, usage, interruption and HTTP error boundaries. Current release evidence belongs in `protocol-decoupling-acceptance.json`; fixture results and real-provider observations are recorded separately. Deployment remains isolated preview only under R50.

Provider references: [OpenRouter Anthropic configuration](https://openrouter.ai/docs/cookbook/coding-agents/claude-code-integration) and [Azure Responses service path](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/responses?view=foundry-classic). The 2026-10-29 OpenRouter preflight did not allow `anthropic-version` or `anthropic-dangerous-direct-browser-access`; server Messages passed, but real browser Messages is not marked verified.
